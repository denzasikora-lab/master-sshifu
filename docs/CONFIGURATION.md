# Конфигурация Master SSHifu

Среда: терминал Mac, каталог `~/Documents/dev/projects/master-sshifu`.
Личная конфигурация находится в `config.json`, исключенном из Git.
При отсутствии используется безопасный образец `config.example.json` с
`backend_ready: false`: системный сеанс не запускается до подготовки сервера.

## Поля config.json

| Поле | Значение образца | Назначение |
| --- | --- | --- |
| `ssh_alias` | `master-sshifu` | Имя профиля из `~/.ssh/config` |
| `ssh_cipher` | `default` | Выбор OpenSSH; `default` сохраняет согласование OpenSSH |
| `ipv6_enabled` | `false` | IPv4 для разрешения доменов; IPv6 включается только при проверенном IPv6-выходе VPS |
| `physical_interface` | `en0` | Реальный физический интерфейс Mac, определенный через `networksetup` |
| `listen_port` | `43180` | Локальный SOCKS движка, только localhost |
| `forward_port` | `43181` | Локальный конец SSH-туннеля |
| `dns_port` | `43153` | Локальный вход DNS |
| `remote_socks_port` | `43190` | Серверный SOCKS, только localhost VPS |
| `backend_ready` | `false` | Явное подтверждение установленной и проверенной серверной части |
| `dns_direct` | `dhcp` | DNS физической сети; можно указать конкретный IP |
| `dns_tunnel` | `1.1.1.1` | DNS через SSH, по TCP |
| `max_restarts` | `5` | Ограничение попыток восстановления SSH, допустимо 0-10 |
| `connect_timeout` | `15` | Тайм-аут SSH в секундах, допустимо 1-60 |

Четыре порта должны отличаться и находиться в диапазоне 1024-65535.
По умолчанию домены разрешаются в IPv4 до передачи серверному SOCKS.
AAAA получает пустой успешный ответ, чтобы приложение не выбирало нерабочий
IPv6-выход VPS. IPv6-маршруты TUN сохраняются. Для проверенного dual-stack VPS
можно явно задать `ipv6_enabled: true`.
Смена серверного порта требует правки `/etc/master-sshifu/server.json` на VPS,
проверки `sing-box check` и перезапуска только службы `master-sshifu`.

Создание конфигурации без сетевых изменений:

```sh
.venv/bin/python tools/configure.py --ssh-alias master-sshifu --interface en0
```

После проверки службы и SOCKS:

```sh
.venv/bin/python tools/configure.py --ssh-alias master-sshifu --interface en0 --backend-ready
```

Команда сохраняет остальные существующие поля. Опция `--backend-ready` не
проверяет VPS сама: последовательность проверки описана в [установке](INSTALL.md).

## Прямые домены и IP

`rules/direct-domains.txt`: один домен или суффикс на строку, комментарии через `#`.
По умолчанию прямые `ru`, `su`, `рф`. Поддомены входят в правило с проверкой
границы: `example.ru` прямой, `example.ru.evil.com` через SSH.
Домены IDN приводятся к ASCII. Для добавления `example.com` запишите отдельную строку.

`rules/direct-cidrs.txt`: отдельные IPv4/IPv6 или сети CIDR для прямого выхода.
Для личных исключений без изменения общих файлов используйте
`rules/local-domains.txt` и `rules/local-cidrs.txt` с тем же форматом.
Они необязательны, добавляются к общим правилам и исключены из Git.
Широкие сети автоматически не добавляются. После изменения правил перезапустите
свой сеанс. Проверка выбранного правила без запуска VPN:

```sh
.venv/bin/python vpn.py match example.ru
.venv/bin/python vpn.py match example.com
```

Это решение по домену, не по стране владельца сайта. `.com` не становится
прямым из-за русского языка. Содержимое страницы `.ru` может грузиться с внешних
доменов через SSH. Для браузера с собственным DoH или старым DNS-кешем итоговую
маршрутизацию нужно проверять отдельно. В системном режиме используется FakeIP,
чтобы сохранить связь домена с соединением.

## Режимы и команды

| Команда | Что делает | Права |
| --- | --- | --- |
| `connect` | Постоянный системный TUN, до Ctrl+C | sudo из учетной записи владельца проекта |
| `stop` | Просит текущий сеанс проекта остановиться | Владелец проекта |
| `status` | Показывает состояние проекта | Владелец проекта |
| `start --mode trial` | SOCKS только TCP через OpenSSH `-D`, без системных маршрутов | Без sudo |
| `start --mode full` | SOCKS TCP и UDP-over-TCP через серверный sing-box | Без sudo, нужен backend_ready |
| `check` | Проверяет конфигурации и SSH-профиль | Без sudo |
| `check --external` | Реальный запрос IP и передача 1 МиБ через запущенный SOCKS | Без sudo |
| `check --local` | Локальные регрессии с временными SSH-серверами | Без sudo |
| `diagnose` | Собирает ограниченные фрагменты журналов в JSON | Без sudo |
| `manual-check --duration 300` | Ограниченный системный сеанс для ручной приемки | sudo, отключение другого VPN вручную |
| `protected-check --expected-ip IP` | Ограниченные адреса TUN и аварийные пробы при включенном исходном VPN | sudo, только диагностическая приемка |
| `cleanup-audit` | Проверяет закрытый системный журнал владения, без изменения сети | sudo для закрытых файлов |

`protected-check` и `manual-check` меняют тестовые маршруты, поэтому не являются
обычными командами чтения логов. В повседневном `connect` нет KEEP, ожидания
120 секунд и запросов к YouTube/Speedtest перед готовностью. Фоновый контроль
выхода начинается спустя 15 секунд; следующая попытка назначается через
15 секунд после завершения предыдущей. Срок соединения берется из
`connect_timeout` с пределами 3-10 секунд, полный запрос получает еще 3 секунды.
Во время восстановления сначала подтверждается выход через локальный SOCKS,
затем системный выход. Один успешный greeting не считается восстановлением.

Старый `start --mode system` и автоматический возврат других VPN заблокированы
до отдельной приемки. Для обычной работы используйте `connect`.

## Безопасность SSH

Ключ клиента остается в `~/.ssh`, в проекте хранится только его путь в примере.
Проверка host key обязательна; `StrictHostKeyChecking=no` не используется.
Сервер указывается числовым IPv4. `ProxyJump` и `ProxyCommand` не поддерживаются
для этого профиля. SSH-агент и пароли не требуются при запуске: нужен отдельный
доступный ключ для `BatchMode`. Подробности и проверка fingerprint есть в INSTALL.
