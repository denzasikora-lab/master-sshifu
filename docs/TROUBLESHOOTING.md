# Диагностика Master SSHifu

## Одна команда после ошибки

Среда: терминал Mac, каталог `~/Documents/dev/projects/master-sshifu`.
Собирать можно при включенной Amnezia или Happ. Команда не запускает VPN,
не меняет сеть и не обращается в интернет:

```sh
.venv/bin/python vpn.py diagnose
```

Результат содержит путь к `.runtime/diagnostics-ДАТА.json`. Для своего имени:

```sh
.venv/bin/python vpn.py diagnose --output .runtime/problem.json
```

Сборщик читает только известные журналы, до 32 КиБ каждого, включая ротации.
Отсутствующий файл отмечается `null`; ошибка доступа сохраняется в отчете.
Ключи, SSH-конфигурация, окружение и содержимое `config.json` не собираются.
JSON создается с правами `0600`. В нем могут быть IP, домены из ошибок движка
и имена локальных каталогов: просмотрите файл перед передачей третьим лицам.

## Какие журналы смотреть

| Файл | Содержимое |
| --- | --- |
| `/private/var/run/ssh-split-session.log` | JSON-строки: этапы, фоновые HTTP-пробы, ошибки, переподключения и очистка |
| `/private/var/run/ssh-split-session.json` | Последний итог системного сеанса с вложенным состоянием и ошибкой |
| `/private/var/run/ssh-split-vpn.json` | Текущее состояние TUN и ссылка на закрытый журнал владения маршрутами |
| `.runtime/events.log` | История пробных SOCKS-сеансов, исключения, коды выхода и фрагменты stderr |
| `.runtime/ssh.log` | stderr SSH последней попытки пробного режима |
| `.runtime/tun.log` | stderr движка последней попытки пробного режима |

Системный журнал ротируется при 1 МиБ, хранятся три резервных файла `.1`-`.3`.
SOCKS-журнал: 128 КиБ и два резервных файла. Файлы stderr текущего сеанса
отдельные; системные журналы находятся в закрытом временном каталоге из поля
`journal`. При обычном исключении их последние записи копируются в читаемый
отчет. При аварии основного процесса это делает независимый защитник, если
он может завершить отчет. При выключении питания такой гарантии нет.

Просмотр последних событий без sudo:

```sh
tail -n 30 /private/var/run/ssh-split-session.log
cat /private/var/run/ssh-split-session.json
```

`run_id` связывает события одного запуска. `pid` и `child_guard_pids` связывают
их с процессами. Поле `failure_phase` показывает место первоначальной ошибки,
даже если итоговый этап уже `stopped` после успешной очистки. `diagnostics`
содержит traceback и ограниченные фрагменты stderr. `cleanup_seconds`,
`rollback_conflicts` и `cleanup_verified` показывают результат отката.
`child_exit_codes` относятся к процессам-защитникам SSH/TUN; `null` означает,
что на момент записи процесс еще работал.

| Этап | Где искать причину |
| --- | --- |
| `starting` | Параметры, проверка движка, SSH-профиль, свободные порты |
| `ssh_connecting` | Сеть до VPS, host key, авторизация, локальное перенаправление, серверный SOCKS |
| `tun_starting` | Ошибки sing-box, занятый utun99 или порты |
| `routes_configuring` | Совпадение или смена владельца маршрута |
| `dns_configuring` | Регистрация временного DNS через scutil |
| `ready` | Последний health_probe, счетчик consecutive_health_failures, смена физической сети |
| `reconnecting` | Попытки восстановления и stderr SSH |
| `rollback_conflict` | cleanup_error, rollback_conflicts, закрытый журнал владения |

`health_probe` содержит адрес проверочного сервиса, длительность, `ok` и тип
исключения. Поле `path` различает `system` и `socks`, поля `connect_timeout`
и `total_timeout` показывают бюджет. `curl_output` сохраняет ограниченный
текст ошибки curl, например стадию таймаута TLS. `ssh_reconnect_attempt`
записывает новый PID, готовность backend и результат проверки выхода.
Тело успешного ответа сервиса не записывается. Неверный внешний IP считается
ошибкой, а не успешным соединением. Фоновая проверка не воспроизводит видео и
не запускает Speedtest. Готовность TUN сама по себе не доказывает доступность
каждого внешнего сайта.

## Частые ошибки

### Обнаружен другой VPN

Основные маршруты заняты. Команда завершается без ожидания и вмешательства в
Amnezia/Happ. При готовности к ручному переходу отключите другой VPN сами и
повторите `connect`. Для проверки SSH без перехода используйте SOCKS `trial`.

### Permission denied (publickey), Host key verification failed

Среда: Mac. Проверьте профиль и права, не публикуя приватный ключ:

```sh
ssh -G master-sshifu
ssh -T master-sshifu 'id -un'
ls -ld ~/.ssh
ls -l ~/.ssh/master-sshifu_ed25519 ~/.ssh/master-sshifu_ed25519.pub
```

Правильные права: каталог `700`, приватный ключ `600`. После смены VPS
сверьте новый fingerprint через доверенную консоль провайдера. Не отключайте
проверку host key для устранения сообщения.

### Нет ответа SOCKS, хотя SSH доступен

Среда: VPS, административный терминал. Серверный sing-box должен слушать localhost:

```sh
sudo systemctl status master-sshifu --no-pager
sudo journalctl -u master-sshifu -n 100 --no-pager
sudo ss -ltnp 'sport = :43190'
```

Ошибки и предупреждения движка попадают в journald; журнал каждого запроса
отключен. Проверяйте также разрешение TCP forwarding в sshd и совпадение
`remote_socks_port`. При необходимости следите за службой:

```sh
sudo journalctl -u master-sshifu -f
```

### DNS физической сети по DHCP недоступен

Среда: Mac. Убедитесь, что выбран верный `enN`:

```sh
networksetup -listallhardwareports
ipconfig getoption en0 domain_name_server
```

При статической сети укажите реальный доступный DNS этой сети в `dns_direct`.
Не подставляйте случайный публичный сервер: сеть может блокировать прямой DNS.

### Очистка не подтверждена

Повторный Ctrl+C раньше мог прервать `netstat` в финальной проверке уже
выполненного отката и дать ложную ошибку. Теперь служебные команды запускаются
в отдельном сеансе и не получают повторные сигналы передней группы терминала.
Для установленного помощника исправление применяется после его обновления
через `tools/install_launcher.py` при остановленном собственном VPN.

Сначала сохраните `diagnose` и прочитайте `cleanup_error`. Команда `stop`
только просит свой активный сеанс остановиться. Для проверки закрытого
журнала маршрутов есть `cleanup-audit` с sudo; обычным логам sudo не нужен.
Не удаляйте вручную все маршруты utun и не перезапускайте сетевые службы:
новый VPN мог уже занять эти маршруты. Если требуется вернуться к Amnezia,
включите ее вручную после остановки собственного сеанса и проверки отчета.

### Низкая скорость

При нескольких видеопотоках прежний трехсекундный срок проверки мог давать
ложные отказы: SSH продолжал передавать данные, а TLS проверочного запроса
не укладывался в срок. Теперь бюджет увеличен в пределах активности защитника,
а новое соединение принимается только после проверки выхода. На VPS без IPv6
используется явное IPv4-разрешение доменов, включая путь FakeIP.

Записывайте одинаковые сервер Speedtest, сеть и время измерения. Уточните,
используется ли SSH напрямую через физическую сеть. UDP-over-TCP чувствителен
к потерям, задержкам и загрузке канала. Сжатие SSH отключено, поскольку видео
и HTTPS уже сжаты. Смена шифра без замеров не гарантирует ускорения.
Не запускайте несколько тестов скорости одновременно.
