# Проверки и границы приемки

## Локальная регрессия

Среда: Mac, каталог `~/Documents/dev/projects/master-sshifu`, установленный
движок через `tools/install_sing_box.py`, Python 3.12+ и системный OpenSSH.
Пакеты pip не нужны. Запуск без sudo:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Все регрессии находятся в одном `tests/test_all_regressions.py`.
Тесты создают временные ключи и SSH-сервер только на localhost, передают
проверяемые данные через настоящий sing-box, затем завершают свои процессы.
Подключение к настоящему VPS, отключение Amnezia/Happ и изменение системных
маршрутов в эту команду не входят. Для локальных сокетов среда запуска должна
разрешать loopback, а не блокировать весь доступ к сокетам.

Проверяются:

- доменные границы, IDN, прямые CIDR и раздельный DNS TCP/UDP;
- передача полных TCP-пакетов и UDP-over-TCP через временный SSH;
- запрет неверного host key и отсутствие прямого выхода при отказе SSH;
- остановка супервизора, ограниченные повторы, закрытие дочерних процессов;
- независимый защитник после смерти и зависания основного процесса;
- владение маршрутами, частичная настройка и сохранение чужих маршрутов;
- системный сценарий на модели ядра, ошибки DNS и сохранение этапа сбоя;
- отсутствие KEEP и начальных веб-проб в постоянном запуске;
- безопасная распаковка движка и отказ при несовпадении SHA256;
- локальный сбор журналов без сетевых обращений, права результата и ошибки чтения.
- границы правила запуска без пароля, запрет произвольных аргументов,
  защищенность путей и возврат прежней установки при ошибке sudoers.

## Что означает зеленый набор

Локальные проверки транспорта используют настоящий sing-box и OpenSSH,
но системные маршруты в них представлены моделью. Это не измерение скорости
на конкретном провайдере, не реальное воспроизведение YouTube и не развертывание
службы на новом Linux VPS. Проверенный клиентский стенд: macOS arm64, Python 3.14.
Установщик закрепляет также архивы для macOS amd64 и Linux arm64/amd64;
это не заявление о живой приемке всех платформ.

Результат последней локальной проверки и число тестов фиксируются в сообщении
коммита либо при передаче изменения. Не используйте старое число как результат
своего запуска: ориентируйтесь на итог `Ran ... tests` и `OK` в терминале.

## Ручная приемка после установки

Полная последовательность есть в [INSTALL](INSTALL.md). Проверка относится к
конкретной версии, сети и VPS. Запишите дату, версию Python/sing-box, SSH-сервер,
полученный внешний IP, номер результата Speedtest и IP прямого сайта.
Личные адреса и отчеты в публичный репозиторий не добавляйте.

Для испытания с ограничением времени есть `manual-check --duration 300`.
Этот режим требует sudo и предполагает самостоятельное отключение исходного
VPN после подсказки. Через 300 секунд свой туннель останавливается и очищает
собственные изменения; Amnezia/Happ нужно включить вручную. Таймер остановки
не означает автоматическое восстановление другого клиента.

1. С включенным исходным VPN проверьте установку и SOCKS, затем остановите SOCKS.
2. Подготовьте журнал и ограниченный сеанс по инструкции INSTALL.
3. Отключите исходный VPN вручную только после готовности локального защитника.
4. Убедитесь, что внешний IP совпадает с ожидаемым адресом VPS.
5. В YouTube воспроизводите реальное видео 1080p не менее 1-2 минут.
6. В Speedtest дождитесь загрузки и отдачи; проверьте внешний IP и сохраните результат.
7. В Яндекс Интернетометре проверьте физический внешний IP, отличный от VPS.
8. Дождитесь остановки, проверьте отчет очистки, включите исходный VPN вручную.
9. Сохраните `diagnose` и результаты браузера.

Открытие HTML YouTube/Speedtest само по себе не закрывает пункты 5 и 6.
Для повседневного `connect` таймера сеанса нет: он работает до Ctrl+C.
Фоновая проверка контролирует IP выхода, но не заменяет браузерную приемку.
